# 1月24日vs.md — 研读审查结果后的评估与计划

## 一、对审查结论的整体判断
- **可发表性 7/10** 的判断合理：当前稿件有完整实验链路与统一模型，但创新呈“组合改进”而非“全新原理”，这是 Sensors 审稿常见质疑点。
- **主要拒稿风险**判断准确：
  1) 创新性不够突出（“组合优化”容易被认为 incremental）。
  2) 结论可能过度（如 100% PDR 类绝对表述）。
  3) 泛化不足（Intel 单数据集+少场景）。
- **图表信息过载/可读性问题**确实存在：尤其多子图复合图和内嵌表格，阅读成本高，且对 Sensors 审稿人并不友好。

## 二、我认为“最有价值/必须保留”的部分
1) **统一能耗+信道模型**这一条是可信度核心，必须保留并强调。
2) **AERIS 的双 Profile 叙事（E vs R）**可作为论文卖点：
   - E：节能优化、性能稳健
   - R：高可靠但能耗上升
3) **统计检验 + 置信区间**能显著提高可信度，必须保留，但应从“图内表格”移到附录/补充材料。

## 三、我认为“必须修改/收敛”的部分
1) **绝对性结论改写**：
   - “100% PDR across all scales” -> “在所测场景下接近 100% PDR / near-100%”。
2) **概念性宏大术语**（如“distributed optimality curse”）应收敛或补证据。
3) **图 6 六子图信息过载**：将统计表(f)移出主图，仅保留 3–4 个核心子图。
4) **Fig 7/8 的“泛化”措辞**应谨慎：如果仅有 Intel/模拟场景，不应宣称大范围适用。

## 四、下一步“可执行”改进计划（按优先级）

### P0：发表口径与可信度收敛（1–2天）
- 统一口径：
  - 可靠性提升、能耗 trade-off、可复现性、可解释性。
  - 明确 AERIS 优势场景（非移动/中等规模/室内阴影环境）。
- 全面替换绝对性措辞。
- 将统计检验表移入 Supplementary，正文仅保留一句概括（含 Holm-Bonferroni）。

### P1：算法改进（高优先）
- **多网关/多汇聚支持**（核心创新可提升 PDR）：
  - gateway_selector.py：允许 k>1 网关输出
  - aeris_protocol.py：CH 优先连最近网关/多父节点
  - skeleton_selector.py：骨架支持多目标汇聚
- 预期结果：显著提高动态/大规模场景下 PDR，解决“单BS瓶颈”。

### P2：跨层可靠性补丁（中优先）
- 引入轻量 ACK/重传模拟（简化 MAC）：
  - 若成功：提高 robustness；若失败：明确为“近似仿真”。

### P3：CAS 精简或轻量学习（低优先）
- CAS 当前影响有限，建议先做特征收缩与阈值调优。
- DRL 仅作未来方向，不建议本轮投稿主线。
