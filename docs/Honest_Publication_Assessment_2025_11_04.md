## 🚨 严重问题诊断

### 问题1: PDR性能不如经典协议（致命问题）

**事实**：
- Intel数据集: AERIS (45-57%) vs PEGASIS (100%) → **差距42-55pp**
- 合成拓扑: AERIS (78%) vs LEACH/HEED/TEEN (100%) → **差距22pp**
- 大规模: AERIS (39-42%) vs PEGASIS (98%) → **差距56-59pp**

**结论**：AERIS在最关键的指标（数据包投递率）上**全面劣于**经典协议。

### 问题2: 能耗优势不明显

**事实**：
- Intel数据集: AERIS (41.37 J) vs PEGASIS (4.52 J) → **AERIS能耗高9倍**
- 合成拓扑: AERIS (37.39 J) vs PEGASIS (21.98 J) → **AERIS能耗高70%**

**结论**：声称的"能耗优势"不存在，反而在真实数据集上能耗更高。

### 问题3: 论文声称与数据不符

**文档中的声称**：
- "PDR提升30个百分点"
- "43.8%提升"
- "能耗比LEACH/PEGASIS低88%"

**真实数据**：
- PDR **下降** 22-59个百分点（不是提升）
- 能耗在Intel数据集上**高出9倍**（不是低88%）

**结论**：存在严重的数据误报，可能是实验设计缺陷或代码bug。

## 🔍 问题根源分析

### 可能的技术问题

1. **协议逻辑bug**
   - AERIS的数据传输路径可能存在问题
   - 多跳路由导致丢包率增加
   - Gateway/Skeleton机制未按预期工作

2. **能耗计算错误**
   - Intel数据集上能耗异常高（41J vs 4.5J）
   - 可能存在重复计算或遗漏优化

3. **实验设置不公平**
   - AERIS和baseline协议可能在不同条件下运行
   - 环境映射机制可能引入额外开销

4. **PDR统计口径问题**
   - end2end PDR的定义可能不一致
   - 簇内传输vs端到端传输的统计逻辑有误
