```python
# 关键实现1: Welch t-test with Welch-Satterthwaite DOF
def welch_t(x: List[float], y: List[float]) -> Tuple[float, float, float, float]:
    n1, n2 = len(x), len(y)
    m1, m2 = mean(x), mean(y)
    s1, s2 = pstdev(x), pstdev(y)
    var1, var2 = s1 ** 2, s2 ** 2
    denom = math.sqrt(var1 / n1 + var2 / n2)
    t_value = (m2 - m1) / denom  # ✅ 正确实现

    # Welch-Satterthwaite degrees of freedom
    df_num = (var1 / n1 + var2 / n2) ** 2
    df_den = ((var1 / n1) ** 2) / (n1 - 1) + ((var2 / n2) ** 2) / (n2 - 1)
    dof = df_num / df_den  # ✅ 正确实现

    # Cohen's d effect size
    cohen_d = (m2 - m1) / math.sqrt((var1 + var2) / 2)  # ✅ 正确实现
```

   - 500节点: 从99%降至0.8-1.9%

   - 50节点Intel: 55.85% PDR（可接受）

3. **审稿人会质疑**:
   > "为什么50节点有55% PDR，300节点只有3% PDR？是否存在严重的Bug？如果不是Bug，为什么Theorem 1预测决策延迟<25ms（可扩展），但PDR完全崩溃？"

**可能的原因假设**（需要调试验证）:

**假设1: 多层决策失效率累积**
```
AERIS = CAS → Skeleton → Gateway → Safety
每层失效率: p_fail

E2E成功率 = (1 - p_fail)^N_layers
如果p_fail = 0.3，N_layers = 3：
- (1-0.3)^3 = 0.343 = 34.3%（小规模）
- 大规模时p_fail增大到0.5：(1-0.5)^3 = 12.5%
- 超大规模p_fail=0.7：(1-0.7)^3 = 2.7% ✅ 吻合实际
```

**假设2: PCA Skeleton算法在高密度网络失效**
- 300个簇头时，PCA投影可能过度压缩
- Skeleton节点选择不当导致路径阻塞

**假设3: Gateway协调机制在多跳场景冲突**
- k_gw=2个网关不足以服务30+个簇头
- 网关过载导致大量丢包

**建议紧急调试**（P0优先级）:
