# 实验数据问题诊断报告

**日期**: 2026-01-06
**问题**: 实验数据不合理，PDR-能耗权衡比例与设计预期严重不符

---

## 1. 问题描述

### 1.1 观察到的异常

| 模式 | 设计能耗因子 | 设计PDR | 实测PDR | 实测能耗 |
|------|--------------|---------|---------|----------|
| BALANCED | 2.8x | 88% | **96.9%** | 1.294J |
| HIGH_RELIABILITY | 4.5x | 93% | **99.3%** | 1.327J |

**问题**:
- 设计预期能耗差: (4.5-2.8)/2.8 = **60.7%**
- 实际能耗差: (1.327-1.294)/1.294 = **2.5%**
- 差距: **24倍**！

### 1.2 为什么这不可能是真的

按照设计:
- BALANCED: 3次ARQ, 3级功率, 2份中继
- HIGH_RELIABILITY: 5次ARQ, 4级功率, 3份中继

如果这些机制真正工作，能耗差异应该是60%左右，而不是2.5%。

---

## 2. 根本原因分析

### 2.1 能耗模型缺陷 (enhanced_aeris_protocol.py:410-420)

```python
for attempt in range(profile.max_arq_attempts):
    attempt_energy = base_energy * (1 + attempt * 0.1)  # 问题1: 仅10%增长
    total_energy += attempt_energy
    if self.rng.random() < link_success_prob:
        success = True
        break  # 问题2: 首次成功就退出
```

**问题1**: 功率增长因子太小
- 实际CC2420: 每增加3dBm功率，能耗翻倍
- 代码实现: 每次重试仅增加10%能耗
- 应该是: 每次重试增加50-100%能耗

**问题2**: 链路成功率过高
- 代码中link_margin > 10时，成功率=95%
- 对于100m×100m区域，大部分链路在50m以内
- 结果: 几乎所有包首次传输就成功，ARQ不触发

### 2.2 未实现的机制

| 机制 | 设计 | 实现状态 |
|------|------|----------|
| relay_copies (多路中继) | BALANCED=2, HR=3 | ❌ 未使用 |
| rescue_enabled (救援机制) | HR=True | ❌ 未使用 |
| power_step_db | 每次+2dB | ⚠️ 用于链路计算，未用于能耗 |

### 2.3 PDR过高的原因

设计预期PDR:
- BALANCED: 88%
- HIGH_RELIABILITY: 93%

实测PDR:
- BALANCED: 96.9%
- HIGH_RELIABILITY: 99.3%

**原因**: 链路模型过于乐观
```python
# 当link_margin > 10时，prob = 0.95
# 当link_margin > 15时，prob = 0.98
```

在100m×100m区域，平均节点距离~35m，链路质量很高。

## 3. 真实论文中的权衡比例参考

### 3.1 I-LEACH (2021, SN-AS Journal)
- 基线能耗: 1.0x
- 高可靠模式: 2.8x能耗，PDR提升15%

### 3.2 DQN-WSN (2024, IEEE IoT Journal)
- 能效模式: PDR ~85%, Energy 0.8x
- 可靠模式: PDR ~95%, Energy 1.5x
- 权衡: **每10% PDR提升需要70%能耗增加**

### 3.3 HEED/PEGASIS比较 (典型WSN论文)
- 高PDR (>95%) 通常需要2-3x能耗
- 中等PDR (85-90%) 需要1.3-1.5x能耗

## 4. 结论

### 4.1 当前数据不可发表

"2.5%能耗换取96.9% PDR"这个结论：
1. **不符合物理规律**: ARQ重传和功率提升必然增加能耗
2. **与SOTA论文矛盾**: 其他论文报告的权衡比例是我们的10-30倍
3. **仿真模型有缺陷**: relay_copies和rescue_enabled未实现

### 4.2 需要的修复

1. 修正能耗模型：正确累计ARQ能耗
2. 实现relay_copies机制
3. 调整链路模型使其更现实
4. 或者：使用已有的真实实验数据（如Intel Lab基线对比）
