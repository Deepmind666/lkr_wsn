## 三、致命性技术问题诊断

### 3.1 问题1: 大规模网络PDR崩溃 🔴 P0阻塞

#### 症状
```
规模     LEACH   PEGASIS  HEED    TEEN    AERIS_energy  AERIS_robust
50节点   27.9%   96.6%    100%    100%    55.9%         57.5%  ✅ 可接受
300节点  99.5%   99.4%    99.8%   100%    2.9%          4.6%   🔴 崩溃
500节点  98.9%   96.3%    99.7%   100%    0.8%          1.9%   🔴 崩溃
```

#### 根因分析（基于代码审查）

**第一性原理推导**:
```
AERIS路由路径: 节点 → CH → Skeleton → Gateway → BS

理论跳数:
- 50节点: 2-3跳（合理）
- 300节点: 4-6跳（过多）

假设每跳PDR = 0.95:
- 2跳: 0.95² = 90.25% ✅
- 3跳: 0.95³ = 85.74% ✅
- 4跳: 0.95⁴ = 81.45% ⚠️
- 5跳: 0.95⁵ = 77.38% ⚠️
- 6跳: 0.95⁶ = 73.51% ⚠️

实际数据: 300节点PDR = 2.9%
隐含每跳PDR = (0.029)^(1/4) ≈ 0.42 🔴
```

**诊断结论**:
1. **Skeleton/Gateway机制在大规模网络引入过多跳数**
2. **每跳失败率累积导致端到端崩溃**
3. **可能的代码bug**: k_gw=2（网关数量）不足以服务30+簇头

#### 建议修复

```python
# 当前代码（推测）
k_gw = 2  # 固定2个网关

# 建议修改
k_gw = max(2, num_cluster_heads // 15)  # 动态调整
k_sk = max(2, num_cluster_heads // 20)  # 增加骨干节点
```

**如果无法修复**: 必须在论文中明确说明"当前版本支持≤100节点网络"。

### 3.2 问题2: 动态场景PDR偏低 🔴 P0阻塞

#### 症状
```
场景          LEACH   HEED    PEGASIS  TEEN    AERIS_energy  AERIS_robust
走廊移动      99.4%   99.9%   100%     100%    45.9%         48.7%
移动BS        99.1%   99.8%   99.0%    100%    40.2%         44.7%
随机失联      100%    100%    100%     100%    30.7%         36.7%
平均差距      -50.5pp -54.3pp -63.3pp
```

#### 效应量分析

**Cohen's d统计**（来自dynamic_significance.md）:
```
对比                    Cohen's d   效应大小        解释
LEACH vs AERIS_energy   -23.29      极大 (负向)     AERIS显著更差
HEED vs AERIS_energy    -23.57      极大 (负向)     AERIS显著更差
PEGASIS vs AERIS_energy -23.61      极大 (负向)     AERIS显著更差
TEEN vs AERIS_energy    -23.61      极大 (负向)     AERIS显著更差
```

**解释**: |d| > 20 是**极端效应**，相当于药物临床试验中"致命副作用"级别。

#### 根因分析

**为什么动态场景AERIS表现更差？**

1. **多层决策延迟**: CAS → Skeleton → Gateway三层架构，在快速拓扑变化时路径重建滞后
2. **Gateway固定选择**: 网关选择基于静态PCA投影，在节点移动后失效
3. **Safety过度触发**: 动态场景频繁低PDR，触发Safety强制直传，覆盖智能决策

**合理性判断**: ❌ **不可接受**
- 50-70pp的绝对差距过大
- AERIS声称"面向动态环境优化"，但数据完全相反
- 这是**根本性设计缺陷**，非参数调优可解决
